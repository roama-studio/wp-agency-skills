# Міст до WordPress-сайту лише з доступом до адмінки

Два плагіни для сайтів, де є тільки логін у wp-admin, без SSH і FTP.
Сторонні плагіни міграції не використовуються. В адмінці сайту логін і пароль вводить
власник сайту; ШІ-агенти паролів не вводять.

| Плагін | Що робить | Звідки zip |
|---|---|---|
| «Агенція: експорт» | архів сайту (файли + база) для копії в Playground | `qa-kit bridge export-plugin` → `wp-bridge/dist/agency-bridge-export.zip` |
| «Агенція: правки» | застосовує набір правок одного замовлення, з кнопкою «Відкотити» | `qa-kit bridge build ...` → `<папка набору>/agency-bridge-apply-<замовлення>.zip` |

## Для власника сайту: як зробити копію сайту

1. Увійдіть в адмінку сайту партнера.
2. «Плагіни → Додати новий → Завантажити плагін». Виберіть `agency-bridge-export.zip`,
   натисніть «Встановити», потім «Активувати».
3. «Інструменти → Агенція: експорт» → «Почати експорт». Сторінку не закривайте. Видно відсоток
   і розмір архіву. Сайт на 100 МБ готується за кілька хвилин, великий — довше.
4. Коли з'явиться кнопка «Завантажити архів», натисніть її і збережіть файл. Після повного
   завантаження архів одразу видаляється з сайту. Якщо не завантажили, він сам видалиться через 24 години.
5. Там же натисніть «Видалити плагін». Плагін вимкнеться і видалиться разом з архівом.
6. Покладіть архів у папку замовлення і скажіть розробнику, де він лежить.

Що потрапляє в архів:
- усі файли WordPress;
- копія бази.

Що не потрапляє:
- `wp-config.php` з паролями бази;
- `.env`;
- кеш, бекапи (UpdraftPlus тощо), архіви й логи.

Список пропущеного лежить в `export.json` усередині архіву.

## Для власника сайту: як застосувати правки на живому сайті

Робиться після того, як клієнт погодив правки на копії.

1. Адмінка сайту → «Плагіни → Додати новий → Завантажити плагін» → `agency-bridge-apply-<замовлення>.zip` → «Встановити» → «Активувати».
2. «Інструменти → Агенція: правки». Таблиця показує кожну правку і її стан:
   - **Готово до застосування.** На сайті те саме значення, що було в копії.
   - **Вже є на сайті.** Цю правку вже хтось зробив.
   - **Конфлікт.** Після того як ми зробили копію, це місце на сайті змінили. Видно, що очікували
     і що зараз на сайті. Поки є хоч один конфлікт, плагін нічого не змінює. Розробник оновлює набір правок.
   - **Помилка.** На сайті немає потрібного запису, немає права запису у файл теми тощо.
3. «Застосувати правки». Перед записом плагін зберігає резервну копію кожного значення і файлу,
   який змінює. Потім очищає кеш: Elementor, посилання, кеш-плагіни.
4. Перевірте сайт. Якщо щось не так, натисніть «Відкотити»: усе повернеться точно як було.
   Відкат не спрацює, якщо після правок ці місця ще раз змінили. Тоді плагін нічого не чіпає і показує, де саме.
5. «Видалити плагін». Резервні копії лишаються на сайті в закритій папці. Якщо цей самий zip
   завантажити знову, відкотити ще можна.

Повторне «Застосувати» нічого не змінить, бо набір не застосовується двічі.

## Для розробника

```
Q=qa-kit
$Q wp-site import <архів з плагіна експорту>.zip <work>/original --port 9510   # zip розпаковується сам
$Q wp-site import <той самий zip> <work>/edited --port 9511
# ... правки на edited (WP-CLI, файли теми), QA: $Q wp-site compare <work>/original <work>/edited ...
$Q bridge build <work>/original <work>/edited --order <назва> [--include-option options_*] [--note "що змінено"]
$Q wp-site import <той самий zip> <work>/dry --port 9512                       # третя копія для «сухого» прогону
$Q bridge check|apply|rollback <work>/dry <work>/edited/bridge/<назва>/edits.json
```

`build` знаходить зміни сам. Він порівнює бази обох копій і файли активної теми, а значення читає тим
самим PHP-кодом, що й плагін. Адресу копії він замінює назад на адресу живого сайту. Результат:
- `edits.json` — набір. Його ж застосовує WP-CLI по SSH:
  `wp eval-file <плагін>/cli.php edits.json check|apply|rollback`;
- `EDITS.md` — таблиця «було → стане» для менеджера й власника сайту;
- zip плагіна.

Що набір переносить:
- опції;
- поля записів: заголовок, текст, slug, статус, порядок, батько;
- поля записів і термінів, зокрема SCF / ACF;
- назва, slug, опис і батько терміна;
- налаштування елемента Elementor за id елемента. Якщо змінилась структура сторінки (додано
  чи переміщено елементи), переноситься вся сторінка;
- файли активної теми: нові, змінені, видалені.

Що не переносить. Це видно в `EDITS.md`, і zip не збирається без `--allow-unsupported`:
- нові або видалені записи й терміни;
- нові медіа в uploads;
- файли плагінів і батьківської теми;
- зміни плагінів і теми як налаштувань (`active_plugins`, `stylesheet`);
- поля з кількома значеннями;
- власні таблиці плагінів.

Таке робиться вручну в адмінці або по SSH. Нові опції за замовчуванням не беруться: здебільшого
це службові налаштування плагінів (UpdraftPlus створює їх десяток, коли відкривається адмінка).
Опцію, яку створила саме правка, назвіть явно: `--include-option`.

## Безпека

- Обидва плагіни працюють тільки для адміністратора (на мультисайті — для суперадміністратора).
  Кожна дія перевіряє nonce. Редактор і будь-хто інший отримує 403 на сторінках, в AJAX і при завантаженні.
- Архів лежить у `uploads/agency-bridge-<32 випадкові hex>/`. Там є `.htaccess` (Apache), `web.config` (IIS)
  та `index.php`. Віддає архів лише PHP-обробник для адміністратора.
  На nginx `.htaccess` не діє, тож захист там — лише неможливе для вгадування ім'я папки і файлу,
  а архів живе до завантаження або 24 години.
- Набір правок лежить у `edits/payload.php` як PHP-код. Відкритий напряму в браузері, він нічого не віддає.
  Решта PHP-файлів плагінів без WordPress одразу виходять.
- Файли пишуться лише всередину активної теми. Шлях з `..`, «прихований» файл (`.htaccess`), `.phar` або
  невідомий тип відхиляються ще до запису. Вміст кожного файлу перевіряється за sha256.
- Набір не може змінити адресу сайту, плагіни, тему, ролі, адміністратора, cron чи ключі.
  Немає `eval`, плагіни нікуди не звертаються в інтернет.
- Перевірено на PHP 7.4 і 8.3, на MySQL 8.4 і SQLite (Playground). Без розширення zip працює
  запасний варіант PclZip, який є у самому WordPress.

## Перевірки

- `npm --prefix qa_kit test` — чисті частини (`tests/bridge.test.mjs`).
- `node wp-bridge/tests/e2e.mjs php74|engine|admin|elementor ...` — повільні наскрізні перевірки
  в Playground. Як запускати — у шапці файлу.
